# Contributing to Parfait

Thanks for your interest in Parfait. Bug reports and feature ideas go to [Issues](https://github.com/Lopution/Parfait/issues); security issues are reported privately as described in [SECURITY.md](SECURITY.md).

## Project layout

| Path | What lives there |
|---|---|
| `lib/app/` | App shell: navigation (go_router), theme, shared widgets |
| `lib/core/` | Business logic: pixiv API, network policy, downloads, storage, updater |
| `lib/features/` | Screens, one directory per feature |
| `lib/l10n/` | Translations (`app_*.arb`) and the generated localizations |
| `plugins/rhttp/` | The Rust network layer: a fork of [rhttp](https://codeberg.org/Tienisto/rhttp) (reqwest, rustls, tokio) bridged with flutter_rust_bridge, with DoH and ECH support |
| `plugins/flutter_inappwebview_android/` | Patched WebView plugin, used through `dependency_overrides` |
| `test/` | Flutter tests |
| `tool/` | Release, code generation and README asset scripts |

The app is written in Flutter with Riverpod for state. Direct access in mainland China is implemented by the network policy in `lib/core/network/compat/` on top of the Rust transport.

## Requirements

- Flutter **3.47.2** (stable), the version CI uses
- Rust through [rustup](https://rustup.rs/); `rust-toolchain.toml` pins the toolchain and the Android targets, so `rustup toolchain install` in the repository root is enough
- Android SDK with the NDK version Flutter selects, and JDK 17

## Build and run

```bash
git clone https://github.com/Lopution/Parfait.git
cd Parfait
rustup toolchain install
flutter pub get --enforce-lockfile
flutter run --flavor github
```

There are two flavors: `github` (the APKs on Releases, with the in-app updater) and `fdroid` (no self-updater). Debug builds need no signing material. A `github` release build requires the official signing key and fails without it; for a local, non-publishable test build add `-PPIXIV_ALLOW_DEBUG_RELEASE_SIGNING=true`. The in-app updater only works in officially signed builds.

## Checks

CI requires all of these to pass; please run the relevant ones before opening a pull request.

```bash
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
```

When you touch `plugins/rhttp/`:

```bash
tool/frb_check.sh
(cd plugins/rhttp/rhttp && flutter test)
(cd plugins/rhttp/rhttp/rust && cargo fmt --check && cargo test --locked)
```

## Translations

Strings live in `lib/l10n/app_*.arb`; `app_zh.arb` is the template. After adding or renaming keys, regenerate:

```bash
flutter gen-l10n
python3 tool/gen_l10n_lookup.py
```

## Pull requests

- Target `main`. It is protected: pull requests only, the `analyze-and-test` check must pass, and changes land as merge commits.
- Keep a pull request focused, with one to three logical commits and clear English commit messages.
- Rebase onto `main` before review. Resolve `pubspec.lock` or `Cargo.lock` conflicts by regenerating them (`flutter pub get`, `cargo update`), not by hand.
- UI changes: include before/after screenshots in the pull request.

## README images

The framed screenshots and banners in `.github/readme/` are generated by `tool/build_readme_assets.py` from raw device screenshots; see the script's header for inputs and usage.
